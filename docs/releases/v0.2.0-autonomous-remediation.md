**Release Date**: August 24, 2026  
**Status**: Stable / Production Ready  
**Version**: `v0.2.0-autonomous-remediation`

---

## 1. Objective

Phase 12 introduces **Autonomous Refactoring & Code Remediation Agents** for ArchitectAI. The platform can now take detected architectural findings or governance violations, analyze root causes, generate deterministic refactoring proposals and unified diffs, run isolated sandbox typecheck, lint, and unit test validations, enforce strict security rules, and automate Git branch creation and Pull Request generation.

Crucially, **ArchitectAI enforces a strict Human Approval Boundary** — it automatically generates patches, validates regressions, creates branches, and opens Pull Requests, but **never automatically merges PRs or modifies the default branch directly**. Final merge approval remains with a human reviewer.

## 2. Key Features & Highlights

### Database Architecture

- Created `RemediationStatus` (`PROPOSED`, `PLANNING`, `GENERATING`, `VALIDATING`, `READY`, `FAILED`, `REJECTED`, `APPLIED`), `RemediationType`, and `RemediationRiskLevel` enums.
- Created `RemediationPlan`, `RemediationPatch`, `RemediationValidation`, and `RemediationExecution` models with Prisma migration `20260824162806_add_remediation_agent_foundation`.

### Remediation Planner & Classification

- `RemediationPlannerService`: Analyzes findings and classifies them into `AUTO_REMEDIABLE` (e.g. simple circular dependencies), `ASSISTED_REMEDIATION` (e.g. boundary violations, high coupling), or `MANUAL_ONLY` (e.g. large component decomposition, high risk governance rules).

### Patch Generation & Representation

- `RemediationGeneratorService`: Reads target files, computes original SHA-256 hashes (`originalContentHash`), uses refactoring provider abstraction (`IRefactoringProvider`), generates proposed content and unified diff representations, and stores `RemediationPatch` records.

### Security & Threat Model Protection

- `RemediationSafetyService`: Enforces strict safety rules:
  - Path traversal and absolute path rejection (`../`, `/etc/passwd`).
  - Protected file path rejection (`.git/`, `.env`, `secrets.json`, `id_rsa`, `credentials`).
  - Diff size caps (5 files max, 100KB max diff size).
  - Explicit command allowlist validation (`pnpm typecheck`, `pnpm lint`, `pnpm --filter backend test`). Blocks destructive patterns (`rm -rf`, `sudo`, `curl | sh`, `chmod 777`, `git reset --hard`, `git push --force`).
  - Prompt injection isolation: treats repository content, code comments, and markdown strictly as **DATA**, stripping prompt injection override attempts.

### Isolated Sandbox Validation & Stale Patch Protection

- `RemediationValidatorService`: Verifies original file content hashes on disk match `originalContentHash` (stale patch protection). Runs sandbox validations (`pnpm typecheck`, `pnpm lint`, `pnpm --filter backend test`), records `RemediationValidation` output, and updates plan status to `READY` if all pass, or `FAILED` with preserved logs if regressions occur.

### Human Approval Boundary & Git Execution

- `RemediationExecutorService`: Verifies working tree cleanliness and `READY` status, creates branch `architectai/remediation/<type>-<short-id>`, commits changes, pushes branch, and opens GitHub Pull Request via `GithubClientService`.
- Includes explicit PR body disclaimer: _"ArchitectAI did NOT automatically merge this pull request. Final merge approval requires human review."_

### Phase 7 RAG & UI Integration

- `RemediationContextService`: Enriches Phase 7 RAG assistant queries (`"remediation"`, `"fix"`, `"patch"`, `"refactor"`, `"pr"`) with proposed/validated remediation plans and PR links.
- Frontend Remediation Tab: Integrated `RemediationOverview`, `RemediationPlanCard`, `RemediationDiffViewer`, `RemediationValidation`, `RemediationRiskBadge`, `RemediationStatusBadge`, and `RemediationPRLink` components into `/repositories/[id]`.
