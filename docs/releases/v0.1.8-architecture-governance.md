# Release Notes — v0.1.8-architecture-governance

**Release Date**: August 24, 2026  
**Status**: Stable / Production Ready  
**Version**: `v0.1.8-architecture-governance`

---

## 1. Objective

Phase 10 introduces **Architecture Review & Governance Workflows** for ArchitectAI. Authenticated repository owners can now compare architectural states over time, track component and dependency diffs between snapshots, calculate deterministic risk score deltas, evaluate governance rules (such as boundary leaks and circular dependency rejection), and query governance findings via grounded RAG assistant prompts.

## 3. Core Services

- **`ArchitectureSnapshotService`**: Captures deterministic architectural snapshots from Knowledge Graph nodes and edges, architecture analysis, and system designs.
- **`ArchitectureDiffService`**: Compares snapshot states to detect added/removed components, dependency changes, and risk score deltas (`IMPROVED`, `UNCHANGED`, `DEGRADED`).
- **`GovernanceRuleService`**: Manages default global rules (`NO_CIRCULAR_DEPENDENCY`, `NO_FRONTEND_TO_DATABASE`, `NO_DATABASE_TO_FRONTEND`, `EXCESSIVE_COUPLING`, `RISK_SCORE_THRESHOLD`) and repository-specific governance configurations.
- **`GovernanceEngineService`**: Evaluates rules deterministically against analysis findings and snapshot diffs.
- **`GovernanceReviewService`**: Main orchestrator managing Redis concurrency locks (`repository:governance-lock:<repositoryId>`, TTL 600s, `EX 600 NX`), snapshot creation, diffing, rule evaluation, and review status calculation (`PASS`, `PASS_WITH_WARNINGS`, `FAILED`).
- **`GovernanceContextService`**: Injects governance review context into the Phase 7 RAG assistant pipeline.

## 4. REST APIs

- `GET /api/v1/repositories/:id/governance` — Get repository governance summary.
- `POST /api/v1/repositories/:id/governance/review` — Run automated governance review (returns 409 if locked).
- `GET /api/v1/repositories/:id/governance/snapshots` — List architecture snapshots.
- `GET /api/v1/repositories/:id/governance/snapshots/:snapshotId` — Get snapshot details.
- `GET /api/v1/repositories/:id/governance/diffs` — List architecture diffs.
- `GET /api/v1/repositories/:id/governance/diffs/:diffId` — Get architecture diff detail.
- `GET /api/v1/repositories/:id/governance/violations` — List filterable violations.
- `PATCH /api/v1/repositories/:id/governance/violations/:violationId` — Update violation status (`OPEN`, `ACKNOWLEDGED`, `RESOLVED`, `IGNORED`).
- `GET /api/v1/repositories/:id/governance/rules` — List governance rules.
- `POST /api/v1/repositories/:id/governance/rules` — Create custom rule.
- `PATCH /api/v1/repositories/:id/governance/rules/:ruleId` — Update rule settings.
- `DELETE /api/v1/repositories/:id/governance/rules/:ruleId` — Delete custom rule.

## 5. Frontend Governance Interface

- **`GovernanceOverview`**: Top header displaying governance status badge (`PASS`, `PASS_WITH_WARNINGS`, `FAILED`), current risk score, risk delta, and open/critical violation counts.
- **`GovernanceStatusBadge`**: Status badge indicator.
- **`GovernanceRiskDelta`**: Metric indicator displaying risk changes (`IMPROVED`, `UNCHANGED`, `DEGRADED`).
- **`GovernanceViolationTable`**: Filterable table of governance violations with status update options.
- **`GovernanceRules`**: Active rule configuration list with enable/disable toggles.
- **`ArchitectureDiffViewer`**: Diff viewer displaying added/removed components and dependencies.
- **`ArchitectureSnapshotList`**: Chronological timeline list of architecture snapshots.
- **`GovernanceReviewButton`**: Manual governance review trigger button.
- **`GovernanceFindingDetail`**: Slide-over drawer displaying raw violation evidence details.
- Integrated into `/repositories/[id]` page as **"Governance 🛡️"** tab.
