# Release Notes — v0.1.4-semantic-search

**Release Date**: August 24, 2026  
**Status**: Stable / Production Ready  
**Version**: `v0.1.4-semantic-search`

---

## 1. Objective

Phase 6 introduces the **Semantic Search Foundation** for ArchitectAI. The platform now extracts searchable textual content from repository files, computes vector embeddings, stores vector representations in PostgreSQL (using `pgvector`), and performs repository-scoped semantic similarity search with strict ownership controls.

---

## 2. Database Models & Enums

- **`Embedding` Model**:
  - `id`, `repositoryId`, `fileId`, `graphNodeId`, `contentHash`, `content`, `chunkIndex`, `totalChunks`, `model`, `dimensions`, `metadata`
  - `@@unique([repositoryId, fileId, chunkIndex, model])` for idempotent chunk indexing.

- **`SemanticIndex` Model**:
  - `id`, `repositoryId`, `status` (`PENDING`, `RUNNING`, `SUCCESS`, `FAILED`), `filesDiscovered`, `filesProcessed`, `filesSkipped`, `filesFailed`, `startedAt`, `completedAt`, `errorMessage`

- **PostgreSQL Extension**: Added `pgvector` container image (`pgvector/pgvector:pg15`).

---

## 3. Services Implemented

- **`IEmbeddingProvider` & `MockEmbeddingProviderService`**: Provider abstraction generating L2-normalized vector embeddings based on SHA-256 and keyword feature boosting.
- **`EmbeddingService`**: Handles embedding generation, dimension validation, content hash lookup, and persistence.
- **`SearchableContentService`**: Filters supported code & documentation files, injects repository context headers, computes SHA-256 content hashes, and chunks large files deterministically.
- **`SemanticIndexerService`**: Idempotent background indexing with Redis locking (`repository:embedding-lock:<id>`, TTL 600s, NX), stale embedding cleanup, and status tracking.
- **`SemanticSearchService`**: Performs query embedding, cosine similarity calculation, score ranking, file-collapsed result grouping, and ownership enforcement.

---

## 4. REST APIs

- `GET /api/v1/repositories/:id/search?q=...&limit=...` — Perform semantic similarity search.
- `GET /api/v1/repositories/:id/semantic-index` — Check semantic indexing status.
- `POST /api/v1/repositories/:id/semantic-index` — Trigger manual semantic indexing (HTTP 409 if locked).

---

## 5. Frontend Interface

- **`SemanticIndexStatus`**: Status banner showing index state, discovered/processed/skipped file counts, and vector counts.
- **`SemanticIndexButton`**: Indexing trigger button with loading state and 409 conflict error handling.
- **`SemanticSearchBar`**: Query input, limit selector, and search execution.
- **`SemanticSearchResults`**: Ranked search matches displaying file path, language badge, similarity score percentage, and code snippet preview.
- Integrated into `/repositories/[id]` detail page with full light and dark mode support.
