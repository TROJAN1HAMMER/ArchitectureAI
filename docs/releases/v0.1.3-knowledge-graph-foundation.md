# Release Notes — v0.1.3-knowledge-graph-foundation

**Release Date**: August 24, 2026  
**Status**: Stable / Production Ready  
**Version**: `v0.1.3-knowledge-graph-foundation`

---

## 1. Objective

Phase 5 introduces the **Knowledge Graph Foundation** for ArchitectAI. It transforms persisted `RepositoryFile` entries from Phase 4 into a PostgreSQL-backed code/system knowledge graph (`GraphNode` and `GraphEdge`). The graph represents repository structures, directories, source files, and lightweight import dependencies, providing the foundation for future AST parsing and AI system design discovery.

---

## 2. Database Models & Enums

### Enums Added

- **`NodeType`**: `REPOSITORY`, `DIRECTORY`, `FILE`, `MODULE`, `CLASS`, `FUNCTION`, `INTERFACE`, `COMPONENT`, `API_ENDPOINT`, `DATABASE_MODEL`
- **`EdgeType`**: `CONTAINS`, `IMPORTS`, `DEPENDS_ON`, `CALLS`, `EXTENDS`, `IMPLEMENTS`, `EXPOSES`, `USES`, `DEFINES`

### Models Added

- **`GraphNode`**: Represents an entity within a repository graph.
  - `id`, `repositoryId`, `fileId`, `type`, `name`, `qualifiedName`, `path`, `metadata` (JSON)
  - `@@unique([repositoryId, qualifiedName])` for deterministic node uniqueness.

- **`GraphEdge`**: Represents a directed relationship between two graph nodes.
  - `id`, `repositoryId`, `sourceNodeId`, `targetNodeId`, `type`, `metadata` (JSON)
  - `@@unique([repositoryId, sourceNodeId, targetNodeId, type])` to prevent duplicate edges.

---

## 3. Services & Concurrency Locking

- **`KnowledgeGraphService`**: Database CRUD operations for nodes and edges, summary stats, type breakdowns, and depth-based neighborhood traversal.
- **`RepositoryGraphBuilderService`**: Deterministic hierarchy construction (`REPOSITORY` → `DIRECTORY` → `FILE` via `CONTAINS` edges), lightweight import resolution, and Redis concurrency locking (`repository:graph-lock:<id>`, TTL 600s, NX).
- **Sync Integration**: Automatically triggers graph construction upon successful repository file tree synchronization in `RepositorySyncService`.

---

## 4. API Endpoints

- `GET /api/v1/repositories/:id/graph` — Knowledge graph summary statistics and node/edge type breakdowns.
- `POST /api/v1/repositories/:id/graph/build` — Trigger manual graph construction (returns 409 if lock active).
- `GET /api/v1/repositories/:id/graph/nodes` — List graph nodes with type filtering and text search.
- `GET /api/v1/repositories/:id/graph/edges` — List graph edges with type and node filtering.
- `GET /api/v1/repositories/:id/graph/neighborhood/:nodeId` — Neighborhood graph query returning connected nodes and incoming/outgoing edges.

---

## 5. Frontend Interfaces

- **`GraphSummary`**: Stats header showing node/edge counts, node type badges, and last built timestamp.
- **`GraphBuildButton`**: Button triggering graph construction with loading spinner and 409 conflict handling.
- **`GraphNodeList`**: Searchable and filterable graph nodes list.
- **`GraphEdgeList`**: Filterable list of directed relationships.
- **`GraphNeighborhoodView`**: Neighborhood inspector displaying incoming/outgoing connections for a selected node.
- **`/repositories/[id]` Page**: Embedded Knowledge Graph tab with full dark/light theme support.

## 7. Limitations & Deferrals

- **AST Parsing Deferred**: Tree-sitter and deep language-specific AST parsing are deferred to future phases.
- **External Graph Databases Deferred**: PostgreSQL remains the single source of truth for graph data; Neo4j and vector DBs (Qdrant) are deferred.
