# Release Notes — v0.1.2-repository-intelligence

**Release Date**: August 24, 2026  
**Status**: Stable / Production Ready  
**Version**: `v0.1.2-repository-intelligence`

---

## 1. Objective

Phase 4 establishes the **Repository Intelligence Foundation** for ArchitectAI. It extends the GitHub OAuth integration from Phase 3 into a complete metadata and file-tree ingestion pipeline. The system can connect to GitHub repositories, trigger manual or automatic syncs, retrieve complete repository file trees, persist normalized file nodes in PostgreSQL, manage sync lifecycle locks using Redis, and display repository structures in the Next.js UI.

---

## 2. Database Changes

### Models Added & Extended

- **`RepositoryFile` (New Model)**: Stores normalized file and directory tree nodes.
  - `id`, `repositoryId`, `path`, `name`, `extension`, `size`, `sha`, `type` (`blob` or `tree`), `parentPath`, `createdAt`, `updatedAt`
  - `@@unique([repositoryId, path])` ensures idempotency and prevents duplicate file records.

- **`Repository` (Extended)**: Added `language`, `stars`, `forks`, `isArchived`.

- **`RepositorySync` (Extended)**: Added `filesDiscovered` and `filesProcessed` progress counters.

- **`SyncTrigger` (Enum Extended)**: Added `INITIAL` for automatic initial sync upon connecting a repository.

## 3. Architecture & Sync Lifecycle

```
GitHub API
   ↓ (OAuth Token)
GitHubClientService (getTree, getRepository)
   ↓
RepositorySyncService
   ├── Redis Lock (repository:sync-lock:<id>, TTL 600s NX)
   ├── Status: RUNNING
   ├── Fetch GitHub Metadata & Tree
   ├── Bulk Upsert RepositoryFile (Chunks of 50)
   ├── Status: SUCCESS
   └── Lock Release (safely via lock value validation)
   ↓
PostgreSQL
   ↓
Repository Intelligence REST APIs
   ↓
Next.js UI (/repositories/[id])
```

---

## 4. API Changes

- `GET /api/v1/repositories/:id` — Returns repository detail, file count, and last sync state.
- `GET /api/v1/repositories/:id/syncs` — Returns synchronization history list.
- `GET /api/v1/repositories/:id/tree` — Returns normalized file tree with optional `path` and `limit` query parameters.
- `POST /api/v1/repositories/:id/sync` — Triggers repository synchronization with Redis concurrency lock (returns HTTP 409 if already syncing).

---

## 5. Frontend Features

- **`RepositoryCard`**: Card UI showing visibility, language, stars, file count, sync status badge, and action buttons.
- **`RepositorySyncButton`**: Interactive sync trigger with loading state and 409 conflict handling.
- **`RepositorySyncStatus`**: Status indicator badge for PENDING, RUNNING, SUCCESS, and FAILED states.
- **`RepositoryTree`**: Expandable folder hierarchy showing file sizes, extensions, and directory trees.
- **`/repositories/[id]` Page**: Repository detail view with stats grid, sync history table, and repository tree.
